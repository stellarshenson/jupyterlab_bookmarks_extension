Bookmarks panel - design

The design of the JupyterLab extension @stellarshenson/jupyterlab-bookmarks-manager-extension (PyPI jupyterlab-bookmarks-manager-extension) as it is built. Every statement was checked against src/, jupyterlab_bookmarks_manager_extension/, schema/plugin.json, style/base.css and ui-tests/ on 2026-10-28.

An id such as ACC-LINK-37-OPEN-TAB names an acceptance criterion in docs/acc-crit.md. Only closed criteria are cited, and each names the test that proves it. An id that starts with DEF- names a defect in docs/defects.md.

1. Overview

A side-bar panel with four sections. Links, Files and Sessions are each a tree of folders and bookmarks, kept in one JupyterLab setting; Proxy is a flat list of the pages opened through the lab's server proxy, kept in the application state database. Four server routes read the foreground process of each terminal, fetch the favicon of a page on another origin, answer the pages the server's proxy tap saw and answer the settings saved under the old npm name.

  • Frontend: one plugin, @stellarshenson/jupyterlab-bookmarks-manager-extension:plugin, that adds a SidePanel, the tab-menu command, the drag of a tab onto the panel, the tab marks and the row commands; the tree functions of model/tree.ts are pure; Jest tests them with the store, the filter, the Proxy section's list, the marks and the drop target against fakes
  • Server: GET terminals, POST favicon, GET proxy-opens, GET old-settings and POST old-settings under <base_url>/jupyterlab-bookmarks-manager-extension/, all authenticated
  • Storage: the setting bookmarks of the plugin @stellarshenson/jupyterlab-bookmarks-manager-extension:plugin ACC-STORE-77-SETTING; the Proxy section's list under the state key jupyterlab_bookmarks_manager_extension:recent-proxy, outside the settings file ACC-RECENT-93-SECTION
  • Proxy: a wrapper of the tornado log_function setting sees each page opened through the lab's server proxy, by any route, the lab itself excepted ACC-RECENT-109-ANY-OPEN ACC-RECENT-110-NOT-LAB; a row reopens the page the way it was first opened, and an entry leaves the list after recentProxyTtlDays days, 3 by default ACC-RECENT-94-OPEN ACC-RECENT-95-TTL; the section's + button opens the Open Proxy Page dialog ACC-RECENT-111-POPUP
  • Marks: a main-area tab whose page, file or terminal a bookmark records carries a ribbon on its top edge, its panel row a dot, and the current tab's row is tinted; the colour is the setting markColour ACC-MARK-96-TAB-MARK ACC-MARK-97-OPEN-ROW ACC-MARK-98-MARK-COLOUR
  • Top bar: the title with Filter and Refresh; Refresh checks every file bookmark and reads the running terminals again, Filter narrows the sections to a typed text ACC-PANEL-86-REFRESH ACC-PANEL-87-FILTER
  • Drag: a main-area tab dropped on the panel is added as a bookmark of its kind, inside the folder row under the pointer ACC-PANEL-99-DRAG-TAB
  • Side: the panel starts in the left side bar; JupyterLab's own command sidebar:switch (Switch Sidebar Side in the context menu of the panel's side-bar tab) moves it to the right; the extension has no code for this ACC-PANEL-1-LEFT ACC-PANEL-2-RIGHT

2. Decisions taken

The questions the design had to answer, the decision as it is built, and the reason for it.

QuestionDecisionReason
Name of the section for web pages Links The section was meant to hold lab-served pages, pages on other origins and a PNG file path; the working name Webpages did not fit the PNG path. The PNG path itself is out of scope
What a web tab is and how its URL is read A tab whose widget has no document context and whose node holds exactly one <iframe> with an http or https address. The URL is iframe.contentWindow.location.href when it is readable and http(s), else iframe.src ACC-LINK-19-WEB-TAB ACC-LINK-21-URL All four producers of web tabs installed on the workstation - server-proxy:open, help:open, proxy-launcher:open and iframe:open - keep the URL in the iframe src, so one rule covers all of them. A frame on another origin refuses access to its location; src is then the address
How a link reopens A page on the lab's origin opens in the extension's own MainAreaWidget around an IFrame with the sandbox allow-same-origin allow-scripts allow-popups allow-forms allow-downloads allow-modals and the widget id bookmarks-link-<id>; a second click activates that tab. The lab's Content-Security-Policy blocks a frame of another origin. The cost of the one code path: the tab does not come back after a lab reload

How the terminal process is read and which variables are stored os.tcgetpgrp(ptyproc.fd) gives the foreground process group of the terminal's pty. The group leader's argv comes from /proc/<pgid>/cmdline, joined by shlex.join; its cwd from readlink /proc/<pgid>/cwd; its variables are the ones added or changed against /proc/<shell pid>/environ. Never recorded: _, PWD, OLDPWD, SHLVL, LINES, COLUMNS and any name that contains TOKEN, SECRET, PASSWORD, PASSWD, API_KEY or CREDENTIAL in any case ACC-SESS-54-COMMAND ACC-SESS-55-CWD ACC-SESS-56-ENV ACC-SESS-57-SECRETS Measured on a live server. LINES and COLUMNS are excluded because LINES appeared in the measured diff. The handler reads manager.terminals and never calls get_terminal, which creates a terminal that does not exist
What "the same setup" means and how a session reopens Figure 3 shows the click. The first match is a terminal this bookmark started whose shell has not yet read the typed recipe: GET terminals reports bookmark, the shell's JUPYTERLAB_BOOKMARK, equal to the bookmark id, and pending true. Otherwise a running terminal, with or without a tab, matches when its foreground process has the same shell-quoted command and the same cwd, read from a fresh GET terminals on the click. Of several matches, the one whose tab is open wins, otherwise the first listed. A match runs terminal:open {name}. No match: POST api/terminals {cwd, extra_env: {JUPYTERLAB_BOOKMARK: <id>}}, then terminal:create-new {name}, then session.send types export K='v' ...; <command> and Enter. A click while an earlier click of the same bookmark still runs gets that click's promise ACC-SESS-63-MATCH ACC-SESS-64-MATCH-SHELL ACC-SESS-65-OPEN-ACTIVE ACC-SESS-66-OPEN-START ACC-SESS-67-OPEN-CWD ACC-SESS-68-QUOTE ACC-SESS-79-OPEN-ATTACH ACC-SESS-84-OPEN-FRESH ACC-SESS-85-START-ONCE The click never uses the tab-menu snapshot: a process stopped or started in an open tab changes no terminal name, and runningChanged is meant to fire on a change of names only (@jupyterlab/services/src/terminal/manager.ts L240-251). Closing a terminal tab leaves the terminal running, because shutdownOnClose defaults to false; terminal:open looks for a tab by session name and otherwise runs terminal:create-new {name}, which connects to the running terminal. terminal:create-new {cwd} strips the leading slash of an absolute cwd, so the terminal is started with POST api/terminals. For about 3 s after a start the server reports only the shell, so without the marker a second click started a second terminal (DEF-SESS-7-START-TWICE). After Ctrl-C the marker stays but pending is false, so a click starts a new terminal
Does editing the environment and the command make sense Yes. The bookmark is a launch recipe, text typed into a new terminal; an edit changes the bookmark and never a running process ACC-SESS-70-EDIT-COMMAND ACC-SESS-71-EDIT-ENV ACC-SESS-72-EDIT-CWD ACC-SESS-74-EDIT-ONLY Recognition then uses the edited recipe, so a terminal still running the old command offers Add Tab to Bookmarks ACC-SESS-75-EDIT-MATCH
What the panel header holds and how large the title is The title Bookmarks, then Filter (filterIcon) and Refresh (refreshIcon) as 24 px icon buttons, as in the header of the AI code assistants panel; Filter shows or hides a search box above the sections, Refresh re-checks every file bookmark and reads the running terminals again with its glyph spinning. The title takes the size of the section labels ACC-PANEL-86-REFRESH ACC-PANEL-87-FILTER The reference is the header of jupyterlab_ai_code_assistants_extension. .jp-SidePanel-header sets --jp-ui-font-size0 itself and the title set it again, so the title shrank twice to about 9 px; the header resets its font size to --jp-ui-font-size1 (DEF-PANEL-9-TITLE-SIZE)
How a bookmark or a folder is created in a section The section header holds a + button that opens a menu with New Bookmark... and New Folder; New Bookmark opens the section's edit dialog with empty fields, and Save adds the bookmark in the Folder field's choice, None at the section root ACC-TREE-89-PLUS-MENU ACC-TREE-90-NEW-BOOKMARK One button for the two creations of a section; the dialog is the edit dialog, so the checks of an edit apply to a new bookmark too - the favicon of a link is fetched, a missing file is marked, and an excluded name disables Save
Which names a captured environment leaves out The names of process_reader.py and the secret pattern, plus every name matching an expression of the setting sessionEnvExclude (* any run, ? one character, [...] one of a set, case kept; 29 expressions by default). A name typed in the edit dialog is kept; the dialog refuses only the built-in names and the secret pattern, not the expressions of the setting ACC-SESS-88-ENV-FILTER ACC-SESS-91-ENV-SETTING ACC-SESS-92-ENV-MANUAL The setting is read where the frontend stores a capture, so the server needs no settings access, and an edited list applies without a page reload. The default is the accepted 36-entry list merged into wildcards: PS? also matches PS3 and TERM* also matches TERMINFO
Which pages the Proxy section lists Each page the server's proxy tap sees opened through jupyter-server-proxy, by any route: server-proxy:open, the launcher's tile, a typed URL, also while no lab page is open. One entry per URL, the lab itself not listed. The popup and a row click also record their page, because a closed port gives the tap no open and a reused tab sends no request. The section shows the pages opened within recentProxyTtlDays days that no link bookmarks, newest first, and a click activates the lab tab that shows the page, else runs server-proxy:open with the stored arguments ACC-RECENT-109-ANY-OPEN ACC-RECENT-110-NOT-LAB ACC-RECENT-93-SECTION ACC-RECENT-94-OPEN ACC-RECENT-95-TTL The Star Colonel's words of 2026-10-30: "tap to the proxy, not hook on the proxy open command", "react on any proxy open". The command misses a typed URL and the launcher's tile, which runs no command. A page first opened in a browser tab opens in a browser tab again. He accepted two kinds of listed page: a notebook IFrame of a proxied page, whose headers equal those of a popup lab tab, and a PDF, image, JSON or CSV opened directly, because a content type check needs the private handler._headers. Filtering by the links at render takes the row away while the page is bookmarked and brings it back while the entry lives
How an open bookmark shows on its tab and in its row A 7 by 11 px ribbon hangs from the bookmarked tab's top edge, 3 px from its right border, with a notch at the bottom; a 7 px dot marks the open bookmark's row at its right end, and the current tab's row takes the brand selection tint. The setting markColour picks brand (--jp-brand-color1) or red (--jp-error-color1) ACC-MARK-96-TAB-MARK ACC-MARK-97-OPEN-ROW ACC-MARK-98-MARK-COLOUR The ribbon is the tab label's ::after: jupyterlab_colourful_tab_extension paints a background with !important on every element of a coloured tab, and a pseudo-element is not an element. The mark stays in the marker colour on such a tab

Further decisions

  • A shell in the foreground gives an empty command; such a bookmark reopens a shell in its cwd, and any idle shell in that cwd matches it ACC-SESS-58-SHELL ACC-SESS-64-MATCH-SHELL
  • Variables that login scripts set appear in the diff and are kept; the edit dialog lets the user delete their lines
  • Terminal tabs are recognised by duck typing (widget.content.session.name is a string), not through ITerminalTracker, so @jupyterlab/terminal is not a dependency
  • Every terminal is bookmarkable; a terminal whose foreground process cannot be read (sudo, an exited group leader) is recorded as a plain shell ACC-SESS-59-UNREADABLE
  • Processes that rewrite their argv (npm, npx) stay out of scope: the Star Colonel rejected DEF-SESS-6-ARGV-TITLE on 2026-10-28, because a process title cannot give back the true command line
  • The terminal tab-menu label also refreshes when the context menu opens on a terminal tab, so the label right after Add reads Remove within 2 seconds ACC-SESS-61-MENU-LABEL
  • The server part imports on Windows: process_reader.py imports fcntl and termios inside the pty read, so the package loads without them and no unread input is recorded (DEF-SESS-10-WINDOWS-IMPORT)

3. Data model

The types of src/model/types.ts:

export type SectionKey = 'links' | 'files' | 'sessions';

export interface IFolder {
  kind: 'folder';
  id: string;
  name: string;
  children: Node[];
}

export interface ILink {
  kind: 'link';
  id: string;
  name: string;
  /** Absolute http(s) URL, or a path relative to the lab base URL for a lab-served page. */
  url: string;
  /** Favicon data URL, absent when the page has none or it exceeds the cap. */
  icon?: string;
}

export interface IFileBookmark {
  kind: 'file';
  id: string;
  name: string;
  /** Contents API path, relative to the server root. */
  path: string;
}

export interface ISessionBookmark {
  kind: 'session';
  id: string;
  name: string;
  cwd: string;
  /** Shell-quoted command line; empty for a plain shell. */
  command: string;
  env: Record<string, string>;
}

export type Node = IFolder | ILink | IFileBookmark | ISessionBookmark;

export interface IBookmarks {
  version: 1;
  links: Node[];
  files: Node[];
  sessions: Node[];
}

  • id is UUID.uuid4() from @lumino/coreutils
  • The UI adds only bookmarks of a section's kind to that section and its folders. It creates folders at the section root only, and the Folder field lists root folders only; the type and the tree functions accept any depth ACC-TREE-13-ONE-LEVEL ACC-TREE-14-DEPTH
  • The file-exists state is computed at run time and never stored
  • Default name: a link takes the tab title; a file takes the file name; a session takes <first word of the command, or "shell"> - <base name of the cwd> ACC-LINK-20-MENU-ADD ACC-FILE-40-MENU-ADD ACC-SESS-60-NAME

4. Server API

Base: <base_url>/jupyterlab-bookmarks-manager-extension/, registered by routes.py. Every verb method carries @tornado.web.authenticated; .github/scripts/check_auth.py fails make test when a handler lacks it, and an unauthenticated GET terminals answers 403.

RouteVerbRequestResponse
terminals GET none 200 {"terminals": [{"name", "cwd", "command", "env", "bookmark", "pending"}]}, one entry per terminal in terminal_manager.terminals; env maps names to strings, bookmark is a string, pending a boolean
favicon POST {"url": str}, the URL of a page, scheme http or https 200 {"icon": str | null}; 400 when the body is not JSON, has no url, or the url is not a string with the scheme http or https ACC-LINK-33-FAVICON-INPUT
proxy-opens GET none 200 [{"url": str, "openedAt": int, "newBrowserTab": bool | null}], the opens the proxy tap holds, oldest first; [] when the tap is not installed
old-settings GET none 200 {key: value}, the keys of the settings file saved under the old npm name; {} when the file is absent or cannot be read, or the marker carried exists
old-settings POST none 204; writes the empty marker carried beside the old file, and nothing when the old file is absent

terminals

  • Reads a copy of self.settings["terminal_manager"].terminals; an absent manager gives {"terminals": []}
  • Each entry is read by read_terminal(pid, fd) of process_reader.py in an executor, because /proc reads block
  • bookmark: the shell's JUPYTERLAB_BOOKMARK, or "". pending: FIONREAD on /proc/<shell pid>/fd/0 reports unread input, the recipe line a click sent before the shell was ready
  • The foreground group leader is the shell, or cannot be read: command is "", cwd is the shell's cwd, env is {} ACC-SESS-58-SHELL ACC-SESS-59-UNREADABLE
  • Otherwise command is shlex.join(argv), cwd is the leader's cwd, and env is the added-or-changed diff without the excluded names of section 2
  • The excluded names of process_reader.py are applied on the server; the expressions of sessionEnvExclude are not, because the setting is read in the frontend where a capture is stored ACC-SESS-88-ENV-FILTER
  • The package imports where fcntl and termios are absent: both are imported inside the pty read, and a missing one gives pending false, so the server part loads on Windows (DEF-SESS-10-WINDOWS-IMPORT)
  • Everything else reads /proc. Where it is absent, or os.tcgetpgrp is, the shell gives an empty cwd, command, env and bookmark, so each terminal is listed with empty fields rather than an error

favicon

  • Fetches the page with its own Tornado AsyncHTTPClient: 5 s timeout per request, 1 MB body limit
  • Parses the HTML with html.parser and takes the href of the first <link> whose rel holds the word icon, so rel="shortcut icon" counts; an href that starts with data:image/ is returned as it is, within the same cap ACC-LINK-29-FAVICON-ROUTE
  • No icon link: urljoin(<page URL after redirects>, "favicon.ico"), beside the page ACC-LINK-30-FAVICON-BESIDE
  • The icon answer must have an image/* content type and fit in 32768 characters as a data URL; otherwise icon is null ACC-LINK-32-FAVICON-CAP
  • A fetch error or an HTTP error answer gives {"icon": null}, not an error, because the icon is optional ACC-LINK-31-FAVICON-NONE
  • The server fetches any http(s) URL for an authenticated user; this grants nothing that a terminal does not

proxy-opens and the proxy tap

  • _load_jupyter_server_extension wraps the tornado log_function setting, which tornado calls once per finished request. The wrapper is installed only when jupyter_server_proxy.handlers is in sys.modules; without the proxy the setting stays as it was and the list stays empty. When ProxyHandler or NamedLocalProxyHandler is missing after an upgrade, the server logs one warning and installs nothing ACC-RECENT-121-INERT
  • The wrapper always calls the wrapped function, and catches and logs every exception of its own, because an exception there makes tornado finish the request a second time
  • A request counts as an open by these rules, in order: the handler is a ProxyHandler; the backend port differs from serverapp.port, read at request time, so the lab through the proxy on its own port is dropped, its redirects too, and a service on another allowlisted host on that port number is dropped with it ACC-RECENT-110-NOT-LAB; the method is GET; Sec-Fetch-Dest is document, iframe or frame, or, when the header is absent on a plain HTTP origin, Accept holds text/html; Sec-Purpose is absent; the status is 2xx or 304; the path of Referer does not start with <base>proxy/ or <base><name>/ of a configured or an entry-point server ACC-RECENT-109-ANY-OPEN
  • The backend port is handler.port for a named server, else path_args[-2], by the proxy's route patterns. Neither is a documented API of the proxy, so test_proxy_tap.py asserts them against handlers built from the proxy's real routes ACC-RECENT-122-TAP-API
  • scrub_query removes each query parameter whose name holds token, auth, key, code, state or xsrf, the keys of jupyter_server.log, before the URL is held. It removes the parameter and does not mask its value, so a reopen still loads ACC-RECENT-117-NO-SECRET
  • The held list is a dict in web_app.settings, one entry per URL, at most 100, the oldest dropped; a restart of the server empties it. Each entry holds the scrubbed path and query, the server's openedAt and newBrowserTab: Sec-Fetch-Dest document is true, the others false, and an absent header, as on a plain HTTP origin, null ACC-RECENT-120-REOPEN-MODE
  • After each open the server emits an event of the schema events/proxy_open.yaml, with no data, so a secret cannot leave through it. The event is only the signal; the route is the source, because an open with no lab page listening is lost on the bus ACC-RECENT-123-LAB-CLOSED

old-settings and the carry-over

  • The rename to the scoped npm name moved the settings file, which holds the bookmarks, from <settings dir>/jupyterlab_bookmarks_manager_extension/ to <settings dir>/@stellarshenson/jupyterlab-bookmarks-manager-extension/. The old file is only read; nothing writes, moves or deletes it
  • The route reads the old file with json5, so comments are fine, from user_settings_dir of the running lab. A file that is absent answers {} in silence; a broken file answers {} with a warning in the server log
  • carryOldSettings in model/carry_over.ts applies the answer through the settings registry, one key at a time, and activate awaits it before the store reads the settings and before the panel is added. A key the schema does not declare is skipped. A key with a saved value stays, which also keeps a copy the server extension of stellars_jupyterlab_extensions made at server start. A rejected key is a warning and the registry reloads, because it keeps a rejected value in its copy of the file. A failure of the route, the reload or the post is a console warning and a notification that stays until closed, and the panel loads: a lab whose labextension was upgraded while its server still runs old code answers 404 on the route, the panel looks empty, and an add would hide the old bookmarks, so the notification says to restart the Jupyter server before adding a bookmark
  • Two lab pages that load at once carry at the same moment, and one saves its older copy of the file over a key of the other, which leaves that page with an empty panel. After a carry the file is read once more and a key that is gone is set again; a load with nothing to carry sends no extra request. The post runs after these passes, so both pages get the keys before either posts
  • The carry runs once. When the route answered at least one key, carryOldSettings posts to it after its passes, also when every key already had a saved value or a key was rejected: a rejected value will never pass, and a key already saved may later be removed. A save that fails as a request, with ServerConnection.ResponseError or NetworkError, is not a rejected value: it gives the warning and no post, so the next load carries again. The post writes the empty file <settings dir>/jupyterlab_bookmarks_manager_extension/carried, and read_old_settings, the one reader, answers nothing while that file exists, so Restore to Defaults does not bring the old bookmarks back, in the panel or through the CLI. The marker sits in the settings folder, so a lab with its own settings folder has its own marker
  • With no key answered there is no post, and a post with no old file writes nothing, so a fresh install has no marker folder and a file that appears later is still carried
