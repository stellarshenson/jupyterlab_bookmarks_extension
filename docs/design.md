# Design - bookmarks panel

Source texts: `INTENT.md`, the orchestrator brief (`tmp/workflows/bookmarks-design/brief.md`, "brief") and the three findings in `tmp/workflows/bookmarks-design/` - `investigate-web.md` ("web"), `investigate-terminal.md` ("term"), `investigate-lab.md` ("lab"). A citation such as `lab 3` names the findings file and its section; the finding carries the file and line.

## 1. Overview

A side-bar panel with four sections - Links, Files, Sessions and Proxy - each a tree of folders and bookmarks, except Proxy, a flat list. The three bookmark sections are stored in one JupyterLab setting; the Proxy section's list is stored in the application state database. Three server routes read the foreground process of terminals, fetch cross-origin favicons and answer the pages the server's proxy tap saw.

- Frontend: one `SidePanel` plugin, one tab-menu command, pure model functions that Jest tests
- Server: `GET terminals`, `POST favicon`, `GET proxy-opens` and `GET old-settings`, all authenticated
- Storage: setting `bookmarks` of plugin `@stellarshenson/jupyterlab-bookmarks-manager-extension:plugin`; the Proxy section's list under the state key `jupyterlab_bookmarks_manager_extension:recent-proxy`
- Command line: `jupyterlab-bookmarks` adds a link, file or session bookmark through the running lab's settings API, or writes the settings file when no lab is found (section 8, ACC-CLI-100/101/102/103/104/105)
- Proxy: a wrapper of the tornado `log_function` setting sees each page opened through the lab's server proxy, by any route, the lab itself excepted; a row reopens the page the way it was first opened (section 2, ACC-RECENT-93/94/95, ACC-RECENT-109/110, ACC-RECENT-117 to 123); the section's + button opens the Open Proxy Page dialog (section 5, ACC-RECENT-111 to 116)
- Marks: a tab in the main or down area whose page, file or terminal a bookmark records carries a ribbon on its top edge, and its panel row a dot; the current tab's row is tinted. The colour is the setting `markColour` (sections 3 and 6, ACC-MARK-96/97/98)
- Drag: a main-area tab dragged onto the panel is added as a bookmark where it is dropped - in the section its kind matches, or in the folder row under it - with the checks of the tab menu add (section 5, ACC-PANEL-99-DRAG-TAB)
- Side change: JupyterLab's own `sidebar:switch`; no own code (`lab 1`)
- Findings that replace a brief decision are listed in section 2, marked REPLACED

Further decisions:

- A shell in the foreground gives an empty command; the bookmark reopens a shell in that cwd, and any idle shell in that cwd matches (`term 5`)
- Variables that login scripts set appear in the diff and are kept; the edit dialog lets the user delete lines (`term 5`)
- Terminal tabs are recognised by duck typing (`widget.content.session.name`), not by `ITerminalTracker`, so no `@jupyterlab/terminal` dependency is added (`lab 10`, `term 3`)
- "if sufficiently recognised": every terminal is bookmarkable; a terminal whose foreground process is unreadable (`sudo`, exited group leader) is treated as a shell (`term 1`, "Limits")

## 3. Data model

```ts
export type SectionKey = 'links' | 'files' | 'sessions';

export interface IFolder {
  kind: 'folder';
  id: string;
  name: string;
  children: Node[];
}

export interface ILink {
  kind: 'link';
  id: string;
  name: string;
  /** Absolute http(s) URL, or a path relative to PageConfig.getBaseUrl() for a lab-served page. */
  url: string;
  /** Favicon data URL, absent when the page has none or it exceeds the cap. */
  icon?: string;
}

export interface IFileBookmark {
  kind: 'file';
  id: string;
  name: string;
  /** Contents API path, relative to the server root. */
  path: string;
}

export interface ISessionBookmark {
  kind: 'session';
  id: string;
  name: string;
  cwd: string;
  /** Shell-quoted command line; empty for a plain shell. */
  command: string;
  env: Record<string, string>;
}

export type Node = IFolder | ILink | IFileBookmark | ISessionBookmark;

export interface IBookmarks {
  version: 1;
  links: Node[];
  files: Node[];
  sessions: Node[];
}

/** One page opened through the lab's server proxy, in the state database, not the settings file. */
export interface IRecentProxyEntry {
  /** Absolute URL of the page, in the form of `listedUrl`. */
  url: string;
  /** The name the row shows: typed in the popup, or the page's title. */
  title: string;
  /** The page opened in a browser tab, never in a lab tab. */
  newBrowserTab: boolean;
  /** The widget id of a lab tab that `server-proxy:open` creates or reuses. */
  id?: string;
  /** Milliseconds since the epoch of the last open, by the server's clock or the browser's. */
  openedAt: number;
}
```

- The Proxy section's list is an array of `IRecentProxyEntry` under the state key `jupyterlab_bookmarks_manager_extension:recent-proxy`, newest first; `RecentProxyStore` loads, records and removes entries and emits `changed`
- `pruneRecent` keeps an entry whose age is at most `recentProxyTtlDays` days, so an entry exactly at the limit stays and a TTL of 0 drops every entry older than the current millisecond
- `recordRecent` puts the new entry first, drops an older entry for the same URL, and prunes the rest; `recentWithoutBookmarks` drops the pages a link bookmarks, comparing a link's URL and a page's URL in the form of `listedUrl`, so a link that holds a secret still hides its page, folders included
- `mergeSeen` merges a page the proxy saw: it goes first, a listed page keeps its name, mode and id, and an `openedAt` newer than the observation stays, because the browser's clock can run ahead of the server's (ACC-RECENT-118-NAMED)
- `opensAfter` takes the held opens newer than the watermark, oldest first. Both sides are the server's clock, and a row click's browser time does not move the watermark. The server still holds a removed page, and the watermark keeps it out at the next load (ACC-RECENT-119-REMOVED)
- `listedUrl` is the form a page is listed under: encoded as a browser sends it, with no fragment and no query parameter whose name holds a key of `SECRET_KEYS`. The popup and the row's tab lookup use it, so a popup's page and the proxy's observation of it compare equal under any base URL
- `formatAgo` prints `now`, `Nm ago`, `Nh ago`, `Nd ago`, `Nmo ago`, `Ny ago` with whole-number floors, the labels of the design system's recency emphasis; a negative age, from a server clock ahead of the browser's, prints `now`

- A stored URL is relative iff it does not match `^https?://`; this tells a lab path such as `proxy/8501/` from a remote one, and survives a change of host name (`web`, "Reading the URL")
- `id` is `UUID.uuid4()` from `@lumino/coreutils`
- Folders hold only bookmarks of their section's kind; the UI creates folders at the section root only, the type and the tree functions accept any depth
- The file-exists state is computed at run time and never stored
- Default name: a link takes the tab title; a file takes the file name; a session takes `<first word of command or "shell"> - <cwd base name>`

## 4. Server API

Base: `<base_url>/jupyterlab-bookmarks-manager-extension/`. Every verb method carries `@tornado.web.authenticated`; `.github/scripts/check_auth.py` enforces it in `make test`. The template `hello` route and its test are replaced by these routes.

| Route          | Verb | Request                                         | Response                                                                                                                                              |
| -------------- | ---- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `terminals`    | GET  | none                                            | `200 {"terminals": [{"name": str, "cwd": str, "command": str, "env": {str: str}}]}`, one entry per terminal in `terminal_manager.terminals`           |
| `favicon`      | POST | `{"url": str}`, an `http:` or `https:` page URL | `200 {"icon": str \| null}`; `400` when the body is not JSON, has no `url`, or the scheme is not http or https                                        |
| `proxy-opens`  | GET  | none                                            | `200 [{"url": str, "openedAt": int, "newBrowserTab": bool \| null}]`, the opens the proxy tap holds, oldest first; `[]` when the tap is not installed |
| `old-settings` | GET  | none                                            | `200 {key: value}`, the keys of the settings file saved under the old npm name; `{}` when the file is absent or cannot be read                        |

`terminals`:

- Reads `self.settings["terminal_manager"].terminals`; absent manager gives `{"terminals": []}`
- Each entry is read in an executor, because `/proc` reads block (`term 1`)
- Foreground group leader unreadable or equal to the shell pid: `command` is `""`, `cwd` is the shell's cwd, `env` is `{}`
- `env` is the added-or-changed diff with the exclusions of section 2; `command` is `shlex.join(argv)`
- Linux only (`/proc`); a platform without it gives an empty list. The package imports where `fcntl` and `termios` are absent: the two imports are local to the pty read, and a missing `os.tcgetpgrp` gives an empty command with `pending` false (DEF-SESS-10-WINDOWS-IMPORT)

`favicon`:

- Fetches the page with `AsyncHTTPClient`, 5 s timeout, 1 MB body limit; follows `<link rel~="icon">` or `rel="shortcut icon"` from the HTML (`html.parser`); a `data:` href is returned as is
- No link in the page: `urljoin(page_url, "favicon.ico")`, beside the page (`web` decision 3)
- The icon must have an `image/*` content type and at most 32768 characters as a data URL; otherwise `icon` is `null`
- A fetch error, a non-200 answer or a missing icon gives `{"icon": null}`, not an error: the icon is optional (`lab 9`, `SKILL.md:604-623`)
- The server fetches any `http(s)` URL for an authenticated user; this grants nothing a terminal does not

`proxy-opens` and the proxy tap (`proxy_tap.py`, ACC-RECENT-109, 110, 117, 121, 122, 123):

- `_load_jupyter_server_extension` wraps the tornado `log_function` setting, which tornado calls once per finished request. The wrapper is installed only when `jupyter_server_proxy.handlers` is in `sys.modules`; without the proxy the setting stays as it was and the list stays empty. When `ProxyHandler` or `NamedLocalProxyHandler` is missing after an upgrade, the server logs one warning and installs nothing
- The wrapper always calls the wrapped function, and catches and logs every exception of its own, because an exception there makes tornado finish the request a second time
- A request counts as an open by these rules, in order: the handler is a `ProxyHandler`; the backend port differs from `serverapp.port`, read at request time, so the lab through the proxy on its own port is dropped, its redirects too, and a service on another allowlisted host on that port number is dropped with it; the method is `GET`; `Sec-Fetch-Dest` is `document`, `iframe` or `frame`, or, when the header is absent on a plain HTTP origin, `Accept` holds `text/html`; `Sec-Purpose` is absent; the status is 2xx or 304; the path of `Referer` does not start with `<base>proxy/` or `<base><name>/` of a configured or an entry-point server
- The backend port is `handler.port` for a named server, else `path_args[-2]`, by the proxy's route patterns. Neither is a documented API of the proxy, so `test_proxy_tap.py` asserts them against handlers built from the proxy's real routes
- `scrub_query` removes each query parameter whose name holds `token`, `auth`, `key`, `code`, `state` or `xsrf`, the keys of `jupyter_server.log`, before the URL is held. It removes the parameter and does not mask its value, so a reopen still loads
- The held list is a dict in `web_app.settings`, one entry per URL, at most 100, the oldest dropped; a restart of the server empties it. Each entry holds the scrubbed path and query, the server's `openedAt` and `newBrowserTab`: `Sec-Fetch-Dest` `document` is true, the others false, and an absent header, as on a plain HTTP origin, null
- After each open the server emits an event of the schema `events/proxy_open.yaml`, with no data, so a secret cannot leave through it. The event is only the signal; the route is the source, because an open with no lab page listening is lost on the bus

`old-settings` and the carry-over (ACC-STORE-124-CARRY-OVER):

- The rename to the scoped npm name moved the settings file, which holds the bookmarks, from `<settings dir>/jupyterlab_bookmarks_manager_extension/` to `<settings dir>/@stellarshenson/jupyterlab-bookmarks-manager-extension/`. The old file is only read; nothing writes, moves or deletes it
- The route reads the old file with `json5`, so comments are fine, from `user_settings_dir` of the running lab. A file that is absent answers `{}` in silence; a broken file answers `{}` with a warning in the server log
- `carryOldSettings` in `model/carry_over.ts` applies the answer through the settings registry, one key at a time, and `activate` awaits it before the store reads the settings and before the panel is added. A key the schema does not declare is skipped. A key with a saved value stays, which also keeps a copy the server extension of `stellars_jupyterlab_extensions` made at server start. A rejected key is a warning and the registry reloads, because it keeps a rejected value in its copy of the file. A failure of the route or the reload is a warning, and the panel loads
- There is no marker, so a file that appears later is still carried. The limit: a key removed from the new file, as Restore to Defaults does, comes back from the old file at the next load

Server files under `jupyterlab_bookmarks_manager_extension/`: `routes.py` (registration), `terminals_handler.py`, `process_reader.py` (`/proc` reading, diff, exclusions), `favicon_handler.py`, `favicon_fetch.py`, `proxy_tap.py`, `proxy_opens_handler.py`, `events/proxy_open.yaml`, `old_settings.py`, `old_settings_handler.py`.

Drag a tab onto the panel (ACC-PANEL-99-DRAG-TAB, `panel/tab_drop.ts`):

- A press on a main-area tab that moves 5 px is a drag, the threshold of Lumino's own tab drag. Lumino moves a tab by pointer events, not by HTML5 drag events, so the drop is followed by `pointerdown`, `pointermove` and `pointerup` on the document in the capture phase; the tab's own move between dock areas is left alone
- The tab is found by the `data-id` its title carries, in `app.shell.widgets('main')`, and classified with `classify/tab_kind.ts` as the tab menu does; a tab of no kind (a launcher) has no drop
- Where it lands: a folder row of the tab kind's section takes the bookmark inside that folder; every other part of the panel takes it at the tab kind's section root, including a folder row of another section, because a folder holds the bookmarks of one kind only (section 3); outside the panel nothing lands
- The add is `addTabBookmark` (`tab_add.ts`), so the checks are the tab menu's: a bookmark the section already holds is kept, a terminal is read again, the captured env passes `filterCapturedEnv` and a link gets its favicon
- The mark: while the drag is over the panel the folder row it lands on, or the target section's header, carries `jp-mod-dropTarget`; the mark is removed on the release, on leaving the panel, on Escape and on the context menu, which also abort Lumino's drag
- `elementFromPoint` reads the panel because Lumino's tab drag covers the pointer with its cursor backdrop; the lookup drops the backdrop behind the page for the call, as Lumino's own drop code does

Proxy (`add-recent`, `remove-recent`):

- Recording: `followProxyOpens` reads `GET proxy-opens` at the lab's load, on each event of the schema `.../events/proxy-open` and when the page shows again, because a hidden page can lose its socket. Each open newer than the watermark becomes an entry with `url` = `new URL(open.url, baseUrl).href`, `newBrowserTab: open.newBrowserTab === true`, `id: server-proxy:<url>` and the server's `openedAt`, and `takeSeen` merges them and saves the watermark. Two lab pages each receive the event and each take the page, one row per URL. The list and the watermark are per workspace, so a removal or a typed name stays in that lab page, and a lab page with a new workspace takes every held open. No code observes `server-proxy:open` any more
- The name of a page not yet listed is `readServiceName`, else `seenFallbackName`: `Proxy :<port><path>` for a URL that holds a port, else its path under the lab. A listed page keeps its name (ACC-RECENT-118-NAMED)
- A restored proxy tab loads its page, so the tap sees that load too, and its row moves to the top
- Reading: each render takes `RecentProxyStore.entries`, prunes with `store.recentProxyTtlDays` and `Date.now()`, drops the pages `store.bookmarks.links` bookmarks and applies the filter box's query; the panel listens to `RecentProxyStore.changed`, so a record, a removal, a bookmark and a change of the setting each redraw the section without a page reload
- The click records the page at once, because a lab tab that is open sends no request and the tap sees nothing (ACC-RECENT-94-OPEN). It then activates the main-area tab whose address, through `classifyTab` and `listedUrl`, or the address it opened at, the `src` of its frame, is the page, and otherwise runs the command with the stored arguments. `@jupyterhub/jupyter-server-proxy` finds the widget whose content id equals `id` and activates it, creates it when absent, and `newBrowserTab` opens `window.open(url, '_blank')` and nothing else; a launcher entry's id is `server-proxy:<name>`, a restored tab's is the widget's id
- Add to Bookmarks adds a link at the Links root, `{name: entry.title, url: toStoredUrl(entry.url, baseUrl)}`, and fetches its favicon as any new link does; the Proxy section row then leaves the section because the link bookmarks its URL
- Remove from Proxy removes the entry from the state database; the page itself stays open and a later open records it again. A lab tab of that page still open is restored at a reload and loads its page, which counts as a later open

Open Proxy Page (`dialogs/open_proxy.ts`, ACC-RECENT-111 to 116):

- Open runs `server-proxy:open` with `url` = `<base URL>proxy/<port>/<path without its leading slash>`, `title`, `newBrowserTab` and `id` = `server-proxy:<url>`, so opening the same page again activates its tab. The command's `url` keeps what Path holds, because the page needs it, and the proxy's tab restore saves it in the workspace file. The popup records the page itself just before the run, not awaited, because `window.open` needs the click's user activation: a page on a closed port has a row, and the observation that follows merges with it and keeps the name. The popup records nothing when Port is the port of the lab page's own address, so the lab has no row; a lab behind a port map or a hub still gets a row for its real port. The URL recorded is `listedUrl` of the URL the read ended at, so a page that redirects and a path holding a secret are still one row. The proxy's command does not retitle a found tab and sets the id on the tab's content, so the popup then sets `title.label` on the main-area widget whose `content.id` is that id; the tab and the row take the new name. A lab reload returns that tab to the title of the first open, because the proxy's tracker saves a tab's restore data only when it adds the tab; the row keeps the new name
- The service name is the `<title>` of the page, read with a plain same-origin `fetch` and stopped after 3 s. The `fetch` has `cache: 'no-store'`, because Chromium's HTTP cache holds a second GET of one URL until the first ends, and the read on Open, which follows the read of the `change` by a moment, would spend its limit waiting; a page that answers in 2.9 s then gets its title. The read sends what the browser sends when the page loads in a tab, and not the token and XSRF header of `ServerConnection.makeRequest`, because `jupyter-server-proxy` passes them to whatever listens on the entered port; the body is read only for an OK `text/html` answer and parsed with `DOMParser`, which runs no scripts; white space is collapsed and the value is set as `value`, never as HTML. A page with no title, another answer or a timeout gives the fallback `Proxy :<port><path with its leading slash>`, taken from `listedUrl` of the URL, so it holds no secret of the Path field
- The Name field follows the service name on a `change` of Port or Path: the field is empty with the fallback as its placeholder during the read, so a name typed then does not join it, and holds the title or the fallback when the answer comes, selected while the field has the focus, so the next key replaces it; an answer for a port or path since changed is dropped, and an invalid Port empties the field
- A typed name stays when Port or Path changes; a field the user emptied counts as not typed; Reset Name returns the field to the service name and to following it
- On Open the answer of the last finished read is used when it belongs to the URL on Open, so the tab opens at once; a typed name replaces only its title. With no answer for that URL yet, the case of Enter before a `change` event or of a name typed before Port and Path, Open reads the page and the tab opens when the read ends. The 3 s limit stays under the 5 s for which browsers keep the click's user activation, which `window.open` needs for a browser tab

## 8. Command line

`jupyterlab-bookmarks` adds a bookmark through the running lab's settings API, and writes the
panel's settings file directly when no lab is found. The entry point is
`jupyterlab_bookmarks_manager_extension.cli:main` in `[project.scripts]`, and `add link`, `add file`
and `add session` are its subcommands (ACC-CLI-100/101/102/103/104/105).

- Discovery: one `jupyter server list --json`, bounded at 5 s; the records come in no order. The
  lab is the record matching the first of `JUPYTER_SERVER_URL` (its port and base path, and,
  when `JUPYTER_SERVER_ROOT` is set, an equal `root_dir`), `JUPYTERHUB_SERVICE_PREFIX`,
  `JUPYTER_PORT`; with none of them set, the one record carrying a token. An unmatched name, or
  none or several token-carrying records, is exit 1 listing the running servers. With no record
  and neither `JUPYTER_PORT` nor `JUPYTERHUB_SERVICE_PREFIX` set, the settings file is written.
  A named server that does not answer is exit 1; there is no fallback to the file once a server
  is named
- Address: `http://127.0.0.1:<port><base_url>`, `https` when the record says `secure`, every
  proxy bypassed; never the browser's URL through JupyterHub
- Token: `JUPYTERHUB_API_TOKEN` or `JPY_API_TOKEN` first, then the matched record's own (a
  record reporting `""` sends none), then `JUPYTER_TOKEN`; `Authorization: token <token>` only,
  never in the URL, argv, stdout or stderr
- Endpoint: GET `<address>/lab/api/settings/@stellarshenson/jupyterlab-bookmarks-manager-extension:plugin`; its answer
  carries `raw` (the settings file text as JSON5, comments included) and `settings` (parsed). The
  `raw` text is parsed, merged and PUT as `{"raw": <text>}` with `Content-Type: application/json`;
  a 2xx answer is saved. A lab started without a token answers the PUT 403 until it sees its own
  `_xsrf` value, so the CLI reads the cookie from the base page and sends the PUT once more with
  `X-XSRFToken`. 401 and 403 name the token sources, 404 the server version or a disabled
  extension, 500 the settings text the server cannot parse; a refused connection, a 10 s
  timeout or a TLS failure is exit 1 naming the address
- Merge: one function serves both transports - append the node to the section or the folder's
  `children`, keep every other key. With no `bookmarks` saved the value starts from the old file
  of section 4, because the panel keeps a saved value and would not carry those bookmarks after
  this save. Both write the same text: plain JSON, `indent=2`, a trailing
  newline; the file path goes through `mkstemp` and `os.replace`
- Store, written only when no lab is found:
  `<settings dir>/@stellarshenson/jupyterlab-bookmarks-manager-extension/plugin.jupyterlab-settings`, the file
  `jupyterlab_server` reads and writes for `@stellarshenson/jupyterlab-bookmarks-manager-extension:plugin`. The settings
  dir is `JUPYTERLAB_SETTINGS_DIR` when set, else `jupyter_config_dir()/lab/user-settings`, the
  default `LabApp` uses
- Format: the file is JSON5 and may carry comments; the CLI parses it with `json5`, keeps every
  top-level key other than `bookmarks` as parsed, and writes plain JSON (`indent=2`, a trailing
  newline). A missing file is an empty setting; a `bookmarks` value without the three lists is
  refused, and an absent `version` is set to 1
- Atomic write: `tempfile.mkstemp` in the target folder, write, close, `os.replace`; a failed
  write leaves the old file in place
- Nodes: exactly the schema's shapes - link `{kind, id, name, url}`, file
  `{kind, id, name, path}`, session `{kind, id, name, cwd, command, env}` - with `id` a `uuid4`.
  The name defaults to the URL as typed, the file's basename (a trailing slash ignored) or the
  command; `--name ""` is a usage error
- Folder: `--folder NAME` finds the section's top-level folder of that name and appends to its
  `children`; no match and two matches are refusals that name the section
- Session: `--cwd` defaults to the CLI's current directory, and `--env KEY=VALUE` repeats; an
  empty key or a pair without `=` is a usage error. The env is stored as typed: the CLI applies
  neither the setting `sessionEnvExclude` nor the session dialog's secret-name rule, so a name
  the dialog refuses can reach the settings file
- Links: a URL is accepted when `urlparse` returns a scheme or the text starts with `/`;
  otherwise a usage error asks for `https://`. A file path is stored as typed and never resolved,
  because the CLI may run on another host than the server
- Output and codes: the new id is the only stdout line, every message goes to stderr, and the
  codes are 0 added, 1 refused or failed, 2 usage. A settings file that is not JSON5 is refused
  with the fix: open the Settings Editor once and save, which rewrites the file as JSON
- Visibility: nothing watches the settings file. The panel shows a CLI-added bookmark at its next
  save, because `BookmarkStore.update` reloads the setting first, or after a page reload; the
  `--help` epilog says so
- Tests: pytest `tests/test_cli.py` runs `main()` under an autouse fixture that deletes the
  discovery variables and puts a fake `jupyter` first on `PATH`, so no test reaches a running
  lab: node shapes, defaults, the folder variant, the session defaults, the JSON5 parse refusal,
  the folder refusals and the usage errors, the preserved keys, the shipped skill, and the
  transport - `test_pick_server` (dead decoy first,
  `JUPYTER_SERVER_URL` with the `root_dir` rule, the prefix, the port, an unmatched name,
  several records, the one token-carrying record), `test_token_order` (hub token, record token,
  no header for `""`), `test_api_add` (a local stub: GET, the PUT path, header and body, a kept
  key), `test_api_errors` (401/403, a refused connection) and `test_file_fallback`. Galata
  `ui-tests/tests/cli.spec.ts` spawns the installed script with the same variables cleared and
  `JUPYTER_PORT` set to the test lab's port; the tokenless test lab answers, the page reloads and
  the three rows show. A second test saves a bookmark through the registry, runs the script with no
  lab found, and reads both in the file and in the panel. `test_first_add_starts_from_the_old_file`
  covers the first add before the first page load

- `file://` links and a route serving files outside the server root (`/tmp/paste-files/...png`), because `jupyter_lab_config.py:91-92` turned local-file serving off; the Star Colonel decided this on 2026-10-27
- REPLACED (ACC-TREE-90-NEW-BOOKMARK, 2026-10-28): the New Link action left out on 2026-10-27 is New Bookmark... in the + menu of Links; `file://` links stay out
- Cross-origin pages inside a lab tab
- Reopening a link tab after a lab reload
- Folders deeper than one level in the UI; dragging a bookmark row or a folder to move it; sort and group options
- Import and export; sync between lab instances; a per-root filter as in `jupyterlab-favorites`
- A check that a stored cwd still exists; a missing cwd opens a terminal in the server's directory (`term 2`)

- Translation strings, an `ITerminalTracker` dependency, `AccordionPanel` resizing
